## 1. 왜

신입 직무 85건 중 33건이 그래프에 못 올랐다 (LGES 22 · LGD 4 · LGU 4 · HSAD 3). 수집이 모자란 게 아니라 **어휘가 IT 에 치우쳐** 있어서다.
탈락 직무의 LLM 원출력(`extracted_raw.json`)과 `canon_candidates.txt` 2회 이상 41개를 전부 대조해, 서울대 과목명에 근거가 있는 것만 추렸다.

- Electrochemistry → Chemical Engineering 엣지가 핵심. 어휘 목록에 Electrochemistry 가 있었는데도 전공 raw 는 전기화학 과목을 전부 Chemical Engineering 으로 묶었다 (재추출 v3 에서 확인). 재추출에 기대지 않고 한 홉으로 잇는다.
- ⚠️ 기존 `BMS → Electrochemistry` 는 그대로 뒀다. 두 단계(BMS→Electrochemistry→ChemE)가 되지만 graph_store 는 한 홉만 보므로 BMS 는 여전히 Electrochemistry 계열로만 잡힌다. BMS HW 공고 내용은 회로 설계라 `BMS → Electrical Engineering` 으로 옮기는 게 나을 수도 있음 — **A 판단**.

## 6. 승인 후 절차 (비용)

1. `python build_graph_jobs.py` — LLM 없음, 1분
2. `python build_graph_majors.py` — raw 캐시 재필터, **LLM 0회** (105개 전공이 전부 캐시에 있음)
3. `python check.py` — 확인 3건 + 평가셋 10 + 인터뷰 2. 태거·인터뷰 분석 **LLM 약 20회** (gpt-4o-mini, 수십 원)
4. 데이터 커밋 (코드와 분리), 설명서 10장 수치 갱신

선택: 전공 **재추출**(💰 105회). 새 어휘가 프롬프트 목록에 들어가면 화학부가 Electrochemistry 를, 경영학과가 Human Resources 를 직접 낼 수 있어 "계열(0.5)" 이 "정확(1.0)" 으로 올라간다. 다만 어휘가 123개로 커지면 LLM 이 보수적으로 변하는 현상(통계학과 Statistics 1개 사례) 재점검이 필요해서, **이번 주엔 하지 않는 것을 권한다** — 위 1~3 만으로 신입 52 → 75 가 된다.
