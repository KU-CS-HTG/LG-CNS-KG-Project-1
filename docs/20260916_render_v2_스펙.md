## 2. 블록별 스펙 — `r = run(...)` 의 필드만 쓴다

공통 헬퍼 (모두 `app.py` 안, LLM 없음):

```python
def _pct(score: float) -> int:            # 0.4632 → 46
    return round(score * 100)

def _bar(score: float, width: int = 10) -> str:
    filled = round(min(max(score, 0.0), 1.0) * width)
    return "█" * filled + "░" * (width - filled)

def _one_school(r: dict) -> bool:         # 쟁점 1 — 하드코딩 금지. 학교가 늘면 자동으로 다시 보인다
    return len({m["school"] for m in r["ranking"]}) == 1
```

### A. [전공]  (`m = r["major"]`, `rk = r["ranking"]`)

| 줄 | 내용 | 데이터 |
|---|---|---|
| 1 | `[전공]    {name}` — `_one_school(r)` 이면 학교 생략, 아니면 `{school} {name}` | `m["school"]`, `m["name"]` |
| 2 | `전공 {total}개를 전부 비교했어 — 네 역량과 이어지는 {len(rk)}개 중 1위` | `r["total_majors"]`, `len(rk)` |
| 3 | `✓ {skill} (과목 {n}개) · …` — 정확히 이어진 태그. 과목 수는 근거 개수 | `m["matched_skills"]`, `len(m["evidence"][skill])` |
| 4 | `≈ {tag} → {parent} 계열로 커버 (과목 {n}개)` — 계열로 이어진 태그. 없으면 줄 없음 | `m["family"]` = {태그: 전공 역량}, `m["evidence"][parent]` |
| 5 | `○ 아직 안 이어진 역량 — {tags}` — 어느 쪽으로도 안 이어진 학생 태그. 없으면 줄 없음. 추정 태그는 `(추정)` 표시 | `set(r["tags"]) - matched - family.keys()`, `r["inferred_tags"]` |
| 6~8 | `역량 연결도  {name:<8} {bar} {pct}%` × 상위 3 — 이름 폼 폭은 한글 기준 최대 이름 길이에 맞춤 | `rk[:3]`: `name`, `score` |

- **"어울린다/적합도" 라는 말은 쓰지 않는다.** 점수는 √idf 가중 커버리지(0~1)라 확률이 아니다 — 1위가 0.22 인 케이스(Cloud+Network)도 있다.
- 소수 원값(`0.46`)은 `DEBUG` 일 때만 줄 끝에 `(0.463)` 로 덧붙인다.

### B. [과목]  (`r["subjects"]`)

| 줄 | 내용 |
|---|---|
| 1 | `[과목]    {name}에서 이 역량을 기르는 과목` |
| 2~ | `{subject} → {for 를 ', ' 로}` — **`[… 개설]` 꼬리표 삭제** (출처는 F) |

### C. [직무]  (`j = r["job"]`) — 지금 구조 유지 + 2줄

| 줄 | 내용 |
|---|---|
| 1 | `[직무]    {company} {role} ({career_type})` |
| 2 | `요구 역량 {total}개 중 {covered_count}개 커버` + 계열 있으면 ` (정확 {len(have)} · 계열 {len(family)})` |
| 3 | `✓ {have}` |
| 4~ | `≈ {parent} 계열로 커버 — {children}` (상위 개념별 묶음, 지금과 동일) |
| ✗ | `✗ 교과 밖에서 채울 것 — {gap}` (갭 = **필수** 중 미커버. 우대 미커버는 세지 않는다 — 지금과 동일) |
| 태도 | `요구 태도: {soft_wanted, 맞으면 ✓}` (데이터 있을 때만, 지금과 동일) |
| **URL** | `공고 → {url}` ← 새 줄. 챗봇이 못 주는 출처 | `j["url"]` |

### D. [다음 후보]  (`r["jobs"][1:3]`) — 새 블록, 압축형

각 후보 3줄:
```
{company} {role} ({career_type}) — 요구 {total}개 중 {covered_count}개 커버[ (정확 a · 계열 b)]
  ✓ {have}[  ≈ {family 의 자식들 나열}][  ✗ {gap}][  요구 태도: …]      ← 한 줄에 이어 쓴다. 비어 있는 항목은 생략
  공고 → {url}
```
- 계열은 자식 이름만 나열(상위 개념별 묶음은 1위 직무에서만). 카드 길이 방어.
- 후보가 없으면 블록 자체를 내지 않는다.

### E. [프로필]  — 변경 없음 (`(성향에서 추정: …)` 유지)

## 3. `EXPLAIN_SYSTEM` 수정 3곳 (문단 쪽)

1. 예문의 `"당신은 서울대학교 통계학과에 진학하여"` → `"당신은 통계학과에 진학하여"` (2곳). 카드에서 뺀 학교 이름을 문단이 다시 말하면 쟁점 1 이 무효가 된다.
2. "숫자와 근거는 카드가 이미 보여주므로 다시 나열하지 말고" 뒤에 한 문장 허용 규칙 추가:
   `단, 1단락에서 "전공 {N}개를 모두 비교해 가장 잘 이어진 전공" 이라는 취지를 한 문장으로 말하는 것은 허용한다 — 숫자는 [근거]의 값만 쓴다.`
   → `build_explain_prompt()` 의 [근거] 에 `전체 전공 수: {total_majors} / 이어진 전공 수: {len(ranking)}` 한 줄 추가 (지금은 없음).
3. 규칙 3 은 그대로 (직무 실제 업무 상상 금지).

## 4. 웹 (`webapp.py` / `templates`) — 참고

- `details.html` 은 `render(result)` 텍스트를 그대로 붙이므로 위 변경이 자동 반영된다. 유니코드 바는 고정폭 `<pre>` 에서 그대로 보인다.
- CSS 진짜 progress bar 를 원하면 `render()` 옆에 `render_data(r) -> dict` 를 두고 `{"ranking": [{"name", "pct"}], "job": {...}}` 를 넘겨 템플릿이 `width: {{pct}}%` 로 그리게 한다. 텍스트와 웹이 **같은 숫자**를 쓰는 게 핵심.
- 결과 첫 화면에 문단만 두고 카드를 details 로 보낸 현재 구조는, 쟁점 2·3 결정(숫자는 남긴다)과 맞지 않는다 — 카드(최소 [전공] 블록)를 문단 위나 옆으로. UI 담당 판단.
