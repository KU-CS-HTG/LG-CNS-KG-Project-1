# 전공 역량 추출 필터 수정 (2026-09-15)

담당 C 모듈 `build_graph_majors.py` + `vocab.py`. 9/14 전체 배치(102개 전공) 결과가 오분류였던 원인과 수정 내역.

## 증상

| 전공 | 9/14 결과 | 실제 과목 |
|---|---|---|
| 컴퓨터공학부 | `Security` 하나 | 데이터베이스, 기계학습 개론, 인공지능, 자료구조, 알고리즘, 컴퓨터네트워크, 컴퓨터비전 … (43개) |
| 산업공학과·통계학과 | 빈 리스트 | 회귀분석, 수리통계, 최적화 … |
| 간호학과 | `Security`, `Cloud` | 의료관련감염관리, 디지털 헬스케어와 간호 |

102개 중 22개만 역량이 잡혔고, 잡힌 것도 대부분 억지 매칭. 양쪽(전공↔직무) 공통 Skill 3개 → 추천이 사실상 불가.

## 원인 4가지

1. **근거 과목 2개 규칙** (`if len(real_via) < 2: continue` + 프롬프트 규칙 4) — 대학 과목은 주제당 보통 1개다. "데이터베이스"가 두 과목 있을 리 없으니 Database·NLP·Computer Vision이 전부 탈락. Security만 '인터넷 보안 + 현대암호학 개론' 2개라 우연히 생존.
2. **via 정확 일치** (`v in subject_set`) — LLM이 '기계학습 개론'을 '기계학습'으로 줄여 쓰면 근거 자체가 무효 처리.
3. **억지 매칭** — "목록에서 골라라"만 있고 "없으면 0개가 정답"이 없어서, 간호학과·역사학부에도 무언가를 붙임. 스키마의 "4~8개"도 하한을 강제해 같은 방향으로 밀었다 (9/11 my_service "정확히 3개"와 같은 함정).
4. **[새로 발견] 대표 표기 자기 이름 탈락** — `canonicalize()`는 `CANON` 키(소문자 별칭)만 조회하는데, 대표 표기 63개 중 9개(`Machine Learning`, `Data Analysis`, `Statistics`, `Deep Learning`, `Communication`, `Problem Solving`, `Project Management`, `Version Control`, `Graph DB`)는 자기 이름이 키에 없었다. LLM은 프롬프트의 어휘 목록(= 대표 표기)을 그대로 적으므로, 이 9개는 via가 완벽해도 `None`으로 조용히 버려졌다. 통계학과가 빈 리스트였던 직접 원인.

## 수정

### `build_graph_majors.py`
- **필터 완화**: 근거 과목 1개면 채택. via는 정확 일치 → 없으면 **부분 일치 1건까지** 허용(`match_subject`). 후보가 2개 이상이면 어느 과목인지 모르므로 불채택(안전 쪽).
- **프롬프트**: 규칙 4(2개 이상) 삭제 → "없으면 빈 배열이 정답" 명시 + 실제 오분류 4건을 **음성 예시**로, 정상 3건을 양성 예시로 추가. 스키마 설명 "4~8개" → "없으면 빈 리스트, 최대 8개" (`max_length=8`).
- **3층 보관**: LLM 호출(`call_llm`)과 필터(`filter_skills`)를 분리. 원출력은 `data/majors_raw.json`에 캐시(커밋 대상), 필터 결과는 `data/majors_extracted.json`에 매번 재계산. → **필터 규칙을 고쳐도 LLM을 다시 부르지 않는다.** 실행 로그에 전공별 `raw N / 채택 M (탈락: …)`을 찍어 필터가 무엇을 버렸는지 보이게 함.
- `sample` 모드는 눈으로 확인만 하고 `graph.json`을 쓰지 않는다 (전체 결과를 5개로 덮어쓰는 사고 방지).

### `vocab.py`
- 학문 역량 8개 추가: Algorithm, Data Structure, Operating Systems, Computer Architecture, Software Engineering, Optimization, Signal Processing, Numerical Analysis (컴공·전기정보·수리과학 과목명이 실제로 가리키는 것. LG CNS 신입 공고에도 등장).
- `canonicalize()`가 **대표 표기 자기 이름도 통과**시키도록 `_CANON_VALUES` 조회 추가. 별칭을 일일이 넣지 않아도 앞으로 추가되는 대표 표기가 자동 보호된다.

## 검증 (LLM 호출 없이, 실제 컴퓨터공학부 과목 43개로)

가짜 LLM 출력 6건을 새 필터에 통과:

| LLM 출력 | via | 새 필터 | 예전 필터 |
|---|---|---|---|
| Machine Learning | 기계학습, 인공지능 | ✅ (기계학습 → '기계학습 개론' 부분 일치) | ✗ 정확 일치 실패 + 자기 이름 탈락 |
| Database | 데이터베이스 | ✅ | ✗ 근거 1개 |
| Security | 인터넷 보안, 현대암호학 개론 | ✅ | ✅ |
| Algorithm | 알고리즘, 자료구조 | ✅ | ✗ 어휘에 없음 |
| Data Analysis | 데이터마이닝 개론 | ✅ | ✗ 자기 이름 탈락 |
| Knowledge Graph | 지식그래프 개론 (없는 과목) | ✗ 탈락 (정답) | ✗ |

대표 표기 63개 전부 `canonicalize(v) == v` 확인. 대표 표기가 60개를 살짝 넘었으니(63) A가 정리 시 참고.

## 재실행

```powershell
python .\build_graph_majors.py sample     # 컴공·산공·통계·수리·경영 5개. LLM 5회
python .\build_graph_majors.py            # 전체 105개. LLM 100회, 약 40분 (raw 캐시에 없는 것만)
```
`data/majors_raw.json`이 없으므로 첫 실행은 LLM을 부른다. 이후 필터만 고칠 땐 그냥 재실행(0원).

기대치: 역량 나온 전공 22 → 25~35개(대부분 정상), 공통 Skill 3 → 10~15개, 간호학과·역사학부 0개.

## 발표 5장용 한 줄

> 근거 과목을 2개 이상 요구했더니 대학 과목 특성상 대부분 탈락했다. 1개로 완화하고, 대신 억지 매칭을 막는 음성 예시를 프롬프트에 넣었다. 그리고 어휘 사전이 대표 표기 자기 이름을 못 찾아 9개 역량이 조용히 버려지던 버그를 찾아 고쳤다.
