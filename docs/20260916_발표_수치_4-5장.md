## 4장 도구 — "판정은 LLM 이 아니라 도구가 한다"

### 4-1. 그래프 도식에 적을 숫자

```
(:Major 61) -[:DEVELOPS 174, 근거 과목 454]-> (:Skill 120) <-[:REQUIRES 277 / :PREFERS 170]- (:Job 108)
                                                  ^  |
                                    (:Skill) -[:IS_A 102]-+        ← 자식 → 부모 한 단계 (Oracle → Database)
(:Trait 30) -[:SUGGESTS 7]-> (:Skill)                              ← 성향 → 역량 추정 (0.5)
(:Trait 30) -[:MATCHES 17]-> (:SoftSkill 10) <-[:WANTS 83]- (:Job)  ← 태도 대조 (동점 처리 전용)
```

| 노드 | 수 | 어디서 오나 |
|---|---|---|
| Major | 61 (105 중 역량 1개 이상) | `subject_cleaned.csv` → LLM 추출 → 필터 |
| Job | 108 (172 중 통제 어휘 역량 2개 이상) · 신입 75 | careers.lg.com 9개 계열사 스냅샷 → LLM 추출 → 정규화 |
| Skill | 120 (부모 개념 23 포함) | `vocab.CANON` 대표 표기 중 그래프에 실제 등장한 것 |
| Trait | 30 | 팀원 `user_analysis.STANDARD_TRAITS` |
| SoftSkill | 10 | 공고 표현 34개 → 10개 정규화 (`vocab.SOFT_CANON`) |

| 관계 | 수 | 뜻 | 추론 방향 |
|---|---|---|---|
| DEVELOPS | 174 (근거 과목 454개) | 전공이 이 역량을 기른다 — 과목명이 근거 | — |
| REQUIRES / PREFERS | 277 / 170 | 공고의 필수 / 우대 | — |
| IS_A | 102 | "Oracle 은 Database 의 한 종류" | **위로만** 한 단계 |
| SUGGESTS | 7 | "수리적사고는 Statistics 를 시사" | 추정 (0.5 가중) |
| MATCHES / WANTS | 17 / 83 | 성향 ↔ 태도 ↔ 직무 요구 | 점수 아님, 동점 처리 |

회사별 신입 직무: LGES 51 · CNS 9 · LGD 6 · LGU 5 · HSAD 3 · LGE 1.

### 4-2. 조회 4함수 (`graph_store.py`, LLM 0회)

| 함수 | 입력 → 출력 | 계산 | 화면의 어느 줄 |
|---|---|---|---|
| `find_majors_by_skills(tags)` | 태그 → **전공 전수 순위** | √idf × 근거강도 가중 커버리지, 계열(IS_A) 0.5 | "61개 전공 중 … 1위", 순위 3개 |
| `find_jobs_by_skills(major.skills)` | 전공이 기르는 역량 전체 → 직무 순위 | 집합 코사인 + 계열 0.5, 신입 우선, 동점이면 태도 적합 | "요구 6개 중 6개 커버 (정확 1 · 계열 5)", 갭, 다음 후보 |
| `subjects_for(major, skills)` | 전공 ∩ 직무 역량 → 근거 과목 3개 | 근거 과목 조회 | "[서울대학교 개설]" 꼬리표 |
| `count_majors()` | → 61 | 전수 개수 | "61개 전공 중" |

계산 순서는 **전공 → 직무 → 과목** (화면 순서와 다름). 과목은 전공과 직무를 잇는 다리라 마지막에 뽑는다.

### 4-3. 판정을 LLM 에서 도구로 넘긴 이유 — 확인 3건이 그 증거

| 확인 | 무엇을 보장 | LLM 이 판정하면 |
|---|---|---|
| ① 같은 뜻 다른 문장 2개 → 같은 전공 | **재현성** — 태그가 같으면 딕셔너리 조회 결과가 같다 | 문장이 조금만 달라도 1위가 흔들린다 |
| ② 출력의 모든 고유명사가 `graph.json` 에 존재 | **실존** — 과목명·직무명·역량명을 데이터에서만 꺼낸다 | 그럴듯한 과목명을 지어낸다 |
| ③ 커버 + 갭 = 직무 요구 역량 전체 | **집합 연산** — `요구 − 전공역량` 뺄셈 | "대체로 맞다" 는 말은 하지만 세지는 못한다 |

LLM 이 하는 일은 두 가지뿐: **추출**(공고·과목 → 역량, 오프라인 1회) 과 **표현**(설명 문단·태거). 판정(순위·갭·과목)은 전부 도구.

## 5장 챗봇과 무엇이 다른가 — 나란히 비교

### 5-1. 우리 출력에만 있는 문장 (시연 카드의 실제 숫자)

| 우리 카드 (평가셋 #1·#3·#7) | 챗봇이 못 하는 이유 |
|---|---|
| **"61개 전공 중 46개를 비교한 결과 1위"** | 전체 중에서 고르지 않는다. 떠오른 서너 개 중에 고를 뿐 |
| **"요구 역량 6개 중 6개 커버 (정확 1 · 계열 5)"** — ≈ Programming 계열로 커버: C#, Java, Python | Java 가 Programming 의 한 종류라는 IS_A 를 데이터로 갖고 있어야 나온다 |
| **"다음 후보: LG CNS AI (AX) — 요구 10개 중 7개 커버"** | 세어 본 적이 없다. 집합 뺄셈으로만 나온다 |
| **"[서울대학교 개설]"** 꼬리표 — 과목 3,560개 중에서만 고른다 | 지어낸 과목명에는 붙일 출처가 없다 |
| **"요구 태도: Communication · Collaboration · Problem Solving"** | 공고의 soft_skills 를 세어 둔 것 (108건 중 48건에 데이터) |
| 같은 뜻 답변 2개 → **같은 전공** | 판정이 딕셔너리 조회라 흔들리지 않는다. 평가셋 12건 매번 통과 |

### 5-2. 호출 수 · 토큰 비교 — 세 가지 방식

같은 질문("데이터 분석이 재미있어요 / 통계 수업, 파이썬으로 데이터 정리")에 답하는 세 방식.

| 방식 | 요청당 LLM 호출 | 요청당 입력 토큰 | 결과 |
|---|---|---|---|
| A. 챗봇에 그냥 묻기 | 1 | 수백 | 데이터 없음 → 전공·과목·직무를 **기억으로** 답함. 전수 순위·출처 불가 |
| B. 데이터를 통째로 프롬프트에 넣고 묻기 | 1 | **≈ 115,000 ~ 143,000** (교육과정 CSV 67,284 + 신입 공고 48,026 / 전체 공고 75,171) | 매 요청 컨텍스트 상한 근처. 판정이 LLM → 재현성 없음, 개수 못 셈 |
| **C. 우리 (오프라인 추출 + 그래프 + 도구 판정)** | **2** (태거 + 설명) | **≈ 1,360** (태거 464 + 설명 895) | 전수 순위·갭·출처·재현성 |

- C 의 오프라인 비용은 **1회성**: 직무 추출 172회 ≈ 144,600 토큰 + 전공 추출 105회 ≈ 124,500 토큰 = **≈ 269,000 토큰, 277회**. 결과는 `extracted_raw.json`·`majors_raw.json` 에 캐시 — 오늘 그래프를 6번 다시 만들었지만 LLM 호출 **0회**.
- **손익분기**: B 는 요청당 ≈ 115k. C 의 오프라인 269k 는 B 의 2.3회분 → **3번째 요청부터 C 가 싸고**, 그 뒤로는 요청당 **약 85배**(115k vs 1.36k) 차이.
- `--interview` 는 4~6회 (자기소개 분석 1,635 + 영역 추가 질문 ≤ 2 × 1,097 + 성향 판단 + 태거 464 + 설명 895). 기본 모드(7영역 적응형)는 실측 1세션 20회·25초 — 아래 5-3.

### 5-3. 호출 수 상세 (3장 "호출 수 절감" 에도 씀)

| 구간 | 호출 | 비고 |
|---|---|---|
| 오프라인 · 직무 추출 (`transform_v2.py extract`) | 172회 (추출 성공 171) | 1회성, 캐시 `extracted_raw.json` |
| 오프라인 · 전공 추출 (`build_graph_majors.py`) | 105회 | 1회성, 캐시 `majors_raw.json`. 어휘가 바뀌어도 **필터만 다시** (0회) |
| 오프라인 · 그래프 재생성 (`build_graph_*.py`) | **0회** | 캐시에서 재필터 — 오늘 6회 재생성 |
| 온라인 · `--basic` (3질문) | **2회** = 태거 1 + 설명 1 | 태그 2개 미만이면 재질문 1회 → 최대 3. Q3 는 규칙(LLM 0) |
| 온라인 · `--interview` (축약) | **4~6회** = 자기소개 분석 1 + 부족 영역 질문 0~2 + 성향 판단 1 + 태거 1 + 설명 1 | 관심사는 사전 직행(LLM 0). 성향 판단은 예전 Q3 객관식을 LLM 1회로 대체 (9/16) |
| 온라인 · **기본** (`python app.py`, 7영역 적응형) | **4 ~ 32회**, 실측 1세션 **20회** = 자기소개 1 + 8라운드 × 2(질문 생성 + 분석) + 성향 판단 1 + 태거 1 + 설명 1 | 약 25초. `interview.py` 의 `llm_calls` 는 질문 생성을 안 세서 9 로 나온다(실제 18) — 발표엔 실측값을 쓸 것 |
| 온라인 · `--profile` (저장된 JSON) | **3회** = 성향 판단 1 + 태거 1 + 설명 1 | 대화 없음 |
| 검증 (`check.py`) | ≈ 20회 | 확인 3건 + 평가셋 10 + 인터뷰 2 |

왜 줄었나: ① 판정을 도구로 (순위·갭·과목에 LLM 0) ② 과목 설명이 없어 **전공 단위로 묶어** 추출 (과목 3,829행 → 105회) ③ 원출력 캐시 + 필터 분리 (3층 보관) ④ Q3 는 규칙, 관심사는 사전 직행.

## 재현

```bash
python - <<'EOF'
import json; g = json.load(open("data/graph.json", encoding="utf-8"))
print(len(g["majors"]), len(g["jobs"]), len(g["skills"]), len(g["is_a"]))
print(sum(len(m["develops"]) for m in g["majors"]), sum(len(j["requires"]) for j in g["jobs"]), sum(len(j["prefers"]) for j in g["jobs"]))
EOF
```
토큰: `tiktoken.get_encoding("o200k_base")` 로 `subject_cleaned.csv` 전문, `staged_jobs.json` 의 duty/required/preferred 줄, `app._TAG_PROMPT.format_messages(...)`, `EXPLAIN_SYSTEM + build_explain_prompt(r)` 를 각각 인코딩해 길이를 잰 것. 호출 수는 `app.run`·`interview.interview` 의 호출 지점을 센 것 (`normalize_to_tags` 1, `explain` 1, `analyze_introduction` 1, `analyze_area_answer` ≤ 2).
