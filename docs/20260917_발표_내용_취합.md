## 4. 시행착오 ① — "LLM은 시키면 채운다"

**증상 (9/14 밤, 첫 배치)**: 전공 102개 중 22개만 역량이 잡히고, 잡힌 것도 엉터리 — 컴퓨터공학부 = `Security` 하나, 간호학과 = `Security, Cloud`, 통계학과 = 빈 리스트. 전공·직무 공통 역량 3개 → 추천 불가.

**원인 4가지** (`docs/20260915_전공추출_필터수정.md`)
1. "근거 과목 2개 이상" 규칙 — 대학 과목은 주제당 1개다
2. 과목명 정확 일치 — LLM 이 '기계학습 개론'을 '기계학습'으로 줄여 쓰면 근거 무효
3. **"없으면 빈 배열이 정답"이 없었다** → 간호학과에도 무언가를 붙임
4. 대표 표기 자기 이름이 사전 조회에서 탈락 (`Machine Learning` 을 LLM 이 그대로 적었는데 키가 소문자 별칭뿐)

**같은 뿌리의 사례 4번 더 — "개수를 지정하면 지어낸다"**: 태거 "정확히 3개" → Cloud 를 채움 / 전공 추출 "4~8개" / "최대 5개" / 설명 문단 "3문장 이상" → 없는 직무 업무를 상상. 전부 걷어내고 **"근거가 1개면 1개만"** 으로.

**어떻게 알아챘나**: 결과 파일을 눈으로 열어 봤다 (컴공 = Security 하나는 누가 봐도 이상).
**바꾼 것**: 필터 완화(근거 1개, 부분 일치), 프롬프트에 음성 예시 4건 + "없으면 []", **LLM 호출과 필터를 분리해 원출력을 캐시**(3층 보관) → 규칙을 고칠 때마다 0원으로 재실행. 이후 재추출 v2·v3 는 캐시 재필터로 끝났다.
**배운 문장**: *LLM 에게 "없다"라고 말할 권리를 주지 않으면, 있는 것처럼 말한다.*

## 6. 시행착오 ③ — "점수식은 눈이 아니라 정답지로"

점수식을 **세 번** 바꿨고, 매번 "이상한 1위"가 알려줬다.

| 버전 | 증상 | 원인 | 수정 |
|---|---|---|---|
| 집합 코사인 | "데이터 분석·통계" 에 식물생산과학부·의예과가 **1.0 공동 1위**, 통계학과 0.82 | 역량이 *적은* 전공이 이긴다 | 커버리지(학생 태그 중 채운 비율) |
| idf 가중 | Programming(idf 3.0) 을 1과목만 가진 전공이 통계학과(근거 19과목)를 이김 | 드문 역량이 너무 셈 | **√idf × 근거 강도**(과목 3개면 만점) |
| 직무 코사인 | '영업마케팅: Data Analysis 1개' 직무가 항상 만점 | 역량 1개짜리 공고 | 역량 2개 이상만 그래프에 |
| 동점 | 0.4763/0.4714 가 반올림 경계에서 갈림 | 반올림으로 동점 묶음 | 인접 0.01 안이면 동점 → 태도 적합으로 |

**어떻게 알아챘나가 바뀐 것이 핵심**: 처음엔 눈으로 서너 개 보고 고쳤다 → 고칠 때마다 다른 데가 깨졌다 → **평가셋**("이 입력이면 이 전공이 3위 안") 10건 → 24건(비IT 10, 인터뷰 4). 이후 "새 단어 하나 넣었더니 엉뚱한 직무가 1위" 를 **두 번** 정답지가 잡았다 (HSAD 미디어 ← '데이터 분석 툴', 디지털 기획 ← Tableau/GA). 9/15 저녁 **매칭 동결** — 이후 바꾼 건 어휘와 데이터뿐.
**배운 문장**: *고치기 전에 정답지를 먼저 쓴다. 정답지가 없으면 "고쳤다"와 "옮겼다"를 구분할 수 없다.*

## 7. 시행착오 ④ — "프롬프트 한 단어"

**증상 (9/16 저녁)**: 인터뷰 평가 4건이 실행마다 2/4 ↔ 3/4 로 흔들림. 같은 자기소개에 강점 성향이 `발표력·설득력` ↔ `분석성만`.
**추정과 정정**: 처음엔 "규칙 101줄이 지워졌다"고 봤다 → 실행 시점 프롬프트를 두 버전에서 뽑아 diff 하니 **차이는 약점 관련 줄뿐**. 진짜 원인은 ① MAPPING_RULES 의 `강점으로 나타남` → `강점으로 **명확하게** 나타남` (문턱 상승) ② direction 라벨 3개 → 2개(strength/neutral) 로 줄여 경계 성향이 neutral 로 몰림.
**실험 3회**(가중치 3설정 / 옛 프롬프트 / 라벨 복원) 로 확인 → **약점은 "영역"(묻지 않음)만 삭제하고 "라벨"은 유지**, 규칙 문구 원복 → 두 번 연속 4/4.
**덤으로 배운 것**: gpt-4o-mini 는 temperature 0 에서도 완전히 결정적이지 않다 → 프롬프트를 바꾸면 `check.py` **두 번**.
**배운 문장**: *"약점을 쓰지 않는다"는 결정과 "약점이라는 단어를 지운다"는 구현은 다른 일이었다. 그리고 내 첫 진단은 틀렸었다 — diff 가 맞았다.*
근거: `docs/20260916_인터뷰_평가_회귀_분석.md`

## 10. 그래서 챗봇과 무엇이 다른가

| 우리 카드에만 있는 문장 | 챗봇이 못 하는 이유 |
|---|---|
| "전체 61개 전공 중 … 46개를 선정, 그 중 1위" | 전체를 놓고 비교한 적이 없다 |
| `✓ Data Analysis (과목 7개)` / `○ Python` | 무엇이 이어지고 안 이어지는지 세어 본 적이 없다 |
| "요구 역량 7/10 충족 · Deep Learning(O) …" | 공고를 읽은 적이 없고 도구명=학문명 관계를 모른다 |
| 과목명·직무명이 전부 데이터에 있음 + 공고 링크 | 지어낸 이름에는 출처가 없다 |
| 같은 이야기 → 같은 답 (평가셋 24건 매번 통과) | 판정을 LLM 이 하면 매번 달라진다 |

비용: 데이터를 통째로 프롬프트에 넣고 묻는 방식은 요청당 **≈115,000 토큰**, 우리는 **≈1,400**(지도 만들기 269,000 은 1회). 3번째 요청부터 우리가 싸고 그 뒤 약 85배 차이.

1. **어휘(온톨로지)를 누가 어떻게 관리했나** — 우리는 한 사람 담당으로 정했는데도 동시 편집이 났다. 자동 검증(assert·리포트 숫자) 외에 방법이 있었나?
2. **LLM 출력의 흔들림을 어떻게 다뤘나** — temperature 0 도 흔들렸다. 평가셋을 두 번 돌리는 것 말고 더 나은 방법?
3. **판정을 LLM 에 맡긴 팀은** 재현성·출처를 어떻게 확보했나? 우리는 도구로 넘겼는데 그 대가로 표현이 딱딱해졌다.
4. **사용자 입력을 어디까지 대화로** 받았나 — 우리는 길어질수록 결과가 흔들려 두 영역만 물었다.
