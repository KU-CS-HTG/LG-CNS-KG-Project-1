- 세트 2 를 **거꾸로** 탄 것. 정방향은 학생 태그 → 전공 → (전공 역량 전체) → 직무, 역방향은 직무 요구 역량 → 전공 → 다리 과목. 코드는 `find_majors_by_skills(job.requires + prefers)` 한 줄 — 같은 DEVELOPS/REQUIRES 엣지를 반대 방향으로 순회(traversal)하면 되기 때문. Neo4j 로 쓰면 `(j:Job)-[:REQUIRES]->(s:Skill)<-[:DEVELOPS]-(m:Major)`
- "왜 그래프인가" 의 짧은 답: 관계형이면 조인 순서를 바꿔 쿼리를 새로 짜야 하지만, 그래프는 엣지 방향만 바꾼다
- LLM 0회. 태거도 설명도 없다 — 같은 입력이면 항상 같은 카드 (확인 항목 1번과 같은 이유)
- 컴퓨터공학부가 47% 인 이유: 필수 5개 중 Machine Learning 만 정확 일치, Java·Python·C# 은 Programming 계열(0.5), React 는 Software Engineering 계열 — 계열이 많아 절반씩만 센다
- 예상 질문 "직무를 먼저 정한 학생은요?" → 이 세트로 답한다

## 예상 질문과 한 줄 답

| 질문 | 답 |
|---|---|
| 왜 어학이 없나? B2B 영업은 외국어가 핵심인데 | 어학은 역량이 아니라 지원 **요건**(OPIc IH 이상). 서울대 과목명으로 영어를 기르는 전공이 없고, Skill 로 세면 어학을 명시한 직무 16건만 불리해진다. 정보로 살리려면 soft 처럼 카드 표시만 (설명서 6-1 표) |
| 왜 서울대만? | 교육과정 데이터가 1개교. 대학 비교 축이 없어 "서울대 교육과정 기준 전공 추천" 으로 정의 |

| LLM 은 어디에 쓰나? | 판정이 아니라 **추출**(공고·과목 → 역량)과 **표현**(설명 문단). 판정은 딕셔너리 조회와 집합 연산 |
